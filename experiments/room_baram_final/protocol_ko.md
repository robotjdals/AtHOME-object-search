# 최종 실험 절차: 학습된 플래너 vs 학습 안 된 플래너 (room_baram)

## 목적
위치를 모르는 물체(unknown)를 찾을 때, 증류 학습한 Qwen3-4B 플래너(어댑터)가 학습하지 않은 같은 모델(기본 Qwen3-4B)보다 효율적으로 찾는지 같은 조건에서 비교한다.
두 플래너의 차이는 다음 장소를 고르는 모델 하나뿐이다(같은 프롬프트, 씬그래프, 목표 지점, 주행, 인식, 발견 판정).
명령은 확정된 물체 이름으로 보낸다. 명령 해석 LLM은 비교 대상이 아니다.

## 실험 전에 고정할 것
- 코드: 실험 직전 커밋하고 커밋 번호를 아래에 적는다. 실험 중에는 코드와 설정을 바꾸지 않는다.
- 설정: `configs/robot/room_baram.yaml` (명령당 시간 예산 600초, 인식 신뢰도 0.35, CLIP 5위, 목표 거리 가구 1.0 m / standalone 2.0 m).
- 그래프와 지도: `outputs/room_baram/graph.json`, `room_baram_demo.yaml`.
- 플래너 서버: 랩 서버 vLLM. 어댑터 v1(room, workspace, search_location)과 기본 모델 qwen3-4b가 같은 서버에 있다.
- 검출기: 실험 내내 한 곳만 쓴다(노트북 `detector_host:=local` 권장: 랩 GPU는 다른 사용자에 따라 2배 느려져 시간 지표가 흔들린다).
- 시작 위치: 실험 전에 `save-starts`로 로봇을 다섯 곳(hall, living_room, office, kitchen, bedroom)에 세워 위치와 방향을 저장하고, 모든 시나리오의 최단 경로가 1-30 m인지 검사한 뒤 `starts.json`을 이 폴더에 커밋한다. 실험 중에는 바꾸지 않는다.
- 환경: 같은 조명. 실험 중 사람이 공간과 카메라 시야에 들어가지 않는다(운영자 위치를 미리 정한다).
- unknown 물체(노트북, 책, 식물)는 집 안에 하나씩만 둔다. 쓰지 않는 물체는 공간 밖으로 치운다.
- known 물체(그래프에 있는 물체)는 지도 만들 때 자리 그대로 둔다.
- 배터리: 40회(약 3시간)를 버티는지 확인하고, 충전은 시나리오 사이에만 한다.

## 실행 순서 (`run_order.csv`)
시나리오마다 물체를 한 번 놓고 두 플래너로 연달아 찾는다(물체 위치, 조명, 배터리가 같은 조건).
순서 효과를 상쇄하려고 홀수 시나리오는 trained 먼저, 짝수 시나리오는 base 먼저 한다.
플래너는 명령 사이에 탐색 서버 파라미터로 바꾼다(재시작 없음, 명령 실행 중에는 거절). 매 명령의 기록에 실제로 쓴 플래너가 남는다.

## 진행 (운영자 콘솔의 "실험" 탭)

    ros2 launch athome_bringup realtime_search.launch.py robot_config:=$PWD/configs/robot/room_baram.yaml rviz:=true detector_host:=local console_host:=0.0.0.0 experiment_plan:=$PWD/experiments/room_baram_final/scenarios.csv experiment_record:=window

녹화: 매 회의 명령 전송부터 끝까지를 이 노트북 브라우저의 콘솔 창만 찍어 `videos/run_번호_s시나리오_플래너.mp4`로 저장한다(다른 창에 가려도 그 창만 찍힘). 콘솔 창은 최소화하지 말고, 실험 중 크기를 바꾸지 않는다. 녹화 중에는 상단에 빨간 '녹화 중' 표시가 뜬다.

콘솔(`http://localhost:8080`, 다른 기기는 로그의 토큰 주소)의 "실험" 탭에서 진행한다. 기록은 `outputs/room_baram/experiments/room_baram_final/`에 남는다.
브라우저가 없을 때는 같은 진행기를 터미널에서 쓴다(`scripts/run_final_experiment.py`, 같은 기록 폴더). 둘을 동시에 쓰지 않는다.

1. 시작 위치: 로봇을 다섯 곳에 차례로 세우고 '현재 위치로 저장', 그다음 '경로 검사'로 모든 시나리오가 1-30 m인지 확인한다. `starts.json`을 이 폴더에 복사해 커밋한다.
2. '실험 시작': 시나리오마다 놓을 물체와 책상이 표시된다. 물체를 카메라에서 보이는 쪽에 놓고 '놓았음'.
3. 두 플래너 각각 자동으로: 플래너 설정 → 시작 위치로 이동(주행 모듈) → 인지 준비 확인 → 실제 시작 위치 기록 → 명령 전송 → 끝날 때까지 대기 → 기록 저장.
4. 매 회 끝에 결과와 발견 사진을 보고 '유효' 또는 '무효'(이유 입력)를 누른다. 무효면 같은 회를 바로 다시 한다.
- 자동 이동이 실패하거나 인지 결과가 없으면 '운영자 조치 필요'가 뜬다. 해결하고 '계속'.
- 매 회 시작 전에 RViz에서 위치 추정이 맞는지 본다. 틀렸으면 그 회는 무효.
- '실험 중단': 진행 중인 이동이나 명령을 취소한다(로봇이 멈춘 뒤). 다시 시작하면 유효로 기록된 회는 건너뛴다. 판정 전에 중단한 회는 `aborted: true`, `valid: null`로 기록되고(그때까지의 탐색 기록과 영상 포함) 다시 한다. 진행 표시에서 무효와 따로 '중단 N'으로 센다.
- 실험 중에는 탐색 탭의 명령 입력이 막힌다. 상단의 정지 버튼은 그대로 쓸 수 있다(그 회는 운영자 취소로 실패).

## 판정 기준 (실험 전에 확정, 결과를 본 뒤 바꾸지 않음)
- 성공: 로봇이 발견을 선언했고 발견 사진의 박스 안에 목표가 있다.
- 실패:
  - 오검출: 발견을 선언했는데 사진의 물체가 목표가 아니다.
  - 탐색 소진: 모든 탐색 위치를 돌고 못 찾았다.
  - 시간 초과: 600초를 넘겼다.
  - 시스템 중단: 주행 실패, 프로그램 오류로 더 진행할 수 없다.
  - 운영자 취소: 이유와 관계없이 실패.
- 무효(바로 다시 시행): 시스템과 무관한 원인만. 사람이 시야에 들어옴, 물체를 잘못된 책상에 둠, 위치 추정이 시작부터 틀림, 배터리 문제. 결과를 보기 전에 원인으로 판단한다.
- 사람 개입(일시정지 후 재개 등)은 성공이어도 기록하고, 개입 없는 성공률을 따로 보고한다.

## 지표
- 성공률(95% Wilson 신뢰구간), SPL(실제 시작 위치에서 물체를 놓은 탐색 위치까지의 최단 경로), Search Steps(이동과 관측을 마친 탐색 위치 수), 이동 거리, 시간.
- 같은 시나리오끼리 짝지어 비교한다(방문 수, 이동 거리, 시간의 차이; 부호 검정 또는 Wilcoxon).
- 방마다 책상 두 개가 붙어 있어(사무실 17/18, 주방 11/56, 침실 3/6, 거실 44/79) 옆 책상 방문 중에도 물체가 보일 수 있다. 플래너의 차이는 주로 첫 방 선택에서 나므로, 첫 방이 맞았는지도 함께 보고한다.
- 시나리오의 typical / atypical / neutral 구분은 실험 전에 정한 것이다(노트북·책: 사무실·침실·거실 책상 typical, 주방 책상 atypical; 식물: neutral).
